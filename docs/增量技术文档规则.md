# 一、项目目标

目标是建设一个以 `Loop Controller` 为中心的完整 Data Agent Harness。

`Loop Controller` 是整个 Data Agent 的调度中心，负责控制一次运行从开始到结束的完整生命周期：

```text
用户请求
    ↓
创建或恢复 Harness Run
    ↓
ContextEngine 根据最新运行状态构建 CompiledContext
    ↓
Planning Agent 基于 CompiledContext 规划下一步动作
    ↓
Loop Controller 校验 NextAction
    ├── tool_call
    │      ↓
    │  Tool Runtime 执行高层工具
    │      ↓
    │  返回 ToolResult
    │      ↓
    │  更新 HarnessRunState
    │      ↓
    │  重新构建 CompiledContext
    │      ↓
    │  再次调用 Planning Agent
    │
    ├── ask_user
    │      ↓
    │  保存当前运行现场并暂停
    │      ↓
    │  用户补充或确认
    │      ↓
    │  恢复同一个 Harness Run
    │      ↓
    │  重新构建 CompiledContext
    │
    └── final_answer
           ↓
       Finalization
           ↓
       保存会话、结果、轨迹和 Checkpoint
           ↓
       触发 Memory Formation
           ↓
       返回最终结果
```

必须明确以下职责边界：

- `Loop Controller` 是唯一的运行调度中心，负责循环、状态推进、重试、暂停、恢复、超时、取消和终止。
- `Planning Agent` 只负责理解当前目标并决定下一步动作，不直接执行工具。
- `Tool Runtime` 负责工具注册、参数校验、权限、超时、分发、结果归一化和错误分类。
- `ContextEngine` 负责把当前请求、历史、记忆、附件、RAG、计划进度和工具观察编译成模型可用的上下文。
- `Memory` 负责 Working、Semantic、Episodic、Perceptual Memory 的存储、形成、治理和检索。
- `Finalization` 负责当前运行的最终收尾，并通过现有 `MemoryFormationService` 触发长期记忆形成。
- `Checkpointer` 负责保存可恢复的 LangGraph 运行状态，不替代会话历史表、长期记忆事实表或最终结果表。
- `Planning Agent` 不负责业务计算。
- `Tool Runtime` 不负责任务规划。
- `ContextEngine` 不负责决定下一步调用哪个工具。
- `Memory Formation` 不负责组装当前模型上下文。

# 四、核心设计原则

文档必须明确采用以下原则：

## 4.1 不机械增加 Adapter

不要默认创建：

```text
MemoryAdapter
ContextEngineAdapter
QueryAdapter
AnalysisAdapter
ReportAdapter
```

采用以下判断规则：

- 现有接口符合目标职责时，直接使用。
- 只有存在稳定边界转换时才增加 Adapter。
- 如果只是简单复制字段，不创建 Adapter。
- 现有 LangGraph 节点包含可复用业务逻辑时，优先提取共享 Service。
- Harness 代码直接依赖现有正式接口，不围绕旧图的内部实现建立永久转换层。
- 适配器如果只是为了“让两个类型名字一样”而存在，应删除。

## 4.2 不复制运行状态

当前 `AgentState` 中已经有大量业务字段，例如：

```text
input_text
user_id
conversation_id
thread_id
turn_id
run_id
messages
analysis_plan
analysis_task_results
sql
sql_result
rendered_report
output_text
```

不能再创建一套完全独立、包含同样字段的 `HarnessRunState`。

建议设计为：

```text
HarnessGraphState
├── 保留现有 AgentState 的业务字段和 messages reducer
└── 增加 HarnessControlState
```

其中：

- 业务执行字段继续保持当前扁平结构，兼容现有节点。
- Harness 控制字段集中在 `HarnessControlState`。
- `HarnessControlState` 负责运行阶段、循环次数、重试次数、计划进度、观察结果、确认状态和错误。
- 不允许业务节点各自维护循环控制字段。
- 必须验证该状态能否被当前 LangGraph Checkpointer 正确序列化和恢复。
- 如果状态中使用 Pydantic DTO，必须说明其 Checkpointer 序列化方式。
