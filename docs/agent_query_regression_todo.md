## 本轮发现的问题

- [ ] 多日期字段默认选择不稳定：没有明确指定日期类型时，延迟率选择了 `approved_date_key`，评价指标选择了 `review_answer_date_key`。默认策略应固定为业务默认日期，并且只有用户明确指定时才选择其他日期关系。
- [ ] 日期过滤表达式不统一：`date_key` 是整数代理键，不应使用 `LIKE '2017%'`；年份和月份优先使用 `dim_date.year_month_value`。
- [ ] 部分商品品类展示值包含 `\r`：SQL 可以执行，但最终展示需要清洗原始维度值或在 SQL 中处理。

## 判断规则

- 指标必须使用 meta.metrics.expression_sql。
- 年份默认按下单日期过滤，除非问句明确指定审批、收货、预计送达等日期。
- relationship_type=filter_exists 时必须使用 EXISTS，避免一对多 JOIN 重复聚合。
- 精确召回的维度值使用 raw_value。
- 不存在的维度值不能自动替换成相似的真实值。
- 无数据时允许聚合结果为 NULL；这是数据为空，不代表 SQL 执行失败。
